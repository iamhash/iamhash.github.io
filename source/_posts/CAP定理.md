这里介绍在分布式系统中所运用到的CAP定理。

<!-- more -->

## 概念

一个分布式系统最多只能同时满足**一致性(Consistency)**、**可用性(Availability)**和**分区容错性(Partition tolerance)** 这三项中的两项。

核心：在发生网络分区（P）时，你只能在一致性（C）和可用性（A）之间选一个，不能三者兼得。

- **一致性(C)**：每次读取都会收到最新的写入数据或错误信息。(强一致性)
- **可用性(A)**：每个请求都会收到（非错误的）响应，但不能保证响应包含最新的写入数据。
- **分区容错性(P)**：发生网络分区（即无法互相通信）或节点故障时，系统仍然能够继续运行。

进一步理解，根据 CAP 定理，分布式系统在网络分区发生时，必须在一致性（C）和可用性（A）之间二选一。

- **CP系统**（如ZooKeeper、HBase分布式存储系统）：
  - 分区发生时，优先保证数据一致性。
  - 例如，如果主节点发现自己无法与多数节点通信，会停止写入服务（牺牲可用性A），避免数据不一致。

- **AP系统**（如Redis）：
  - 分区发生时，优先保证可用性。
  - 例如，允许每个分区继续接受读写请求（牺牲一致性C），后续再恢复数据一致。

**应用场景**：金融、支付分布式系统选择满足CP，社交内容分布式系统选择满足AP

```
(补充知识)什么是网络分区
在分布式系统中，节点（服务器）之间通过网络通信协作。**网络分区**指的是由于网络故障（如断网、路由器故障、电缆损坏等），导致系统中的部分节点之间**无法正常通信**。此时，整个系统被分割成多个独立的子网络（称为“分区”），每个分区内的节点可以互相通信，但无法与其他分区的节点通信。
```

## 分区容错性（P）

**分区容错性**指当网络发生分区（节点间通信中断）时或者部分节点故障时，系统仍能继续运行，不因部分节点失联而整体崩溃。它是分布式系统的“生存底线”。

## 可用性（A）

可用性即服务一直可用，且响应时间正常。

一般在衡量一个系统的可用性时，是通过停机时间来计算的

| **可用水平(%)** | **年可容忍停机时间** |
| --------------- | -------------------- |
| 99.9999         | < 1 min              |
| 99.999          | < 5 min              |
| 99.99           | < 53 min             |
| 99.9            | < 8.8 h              |
| 99              | < 3.65 d             |

为了实现可用性：

- 冗余设计：多节点部署，避免单点故障。
- 负载均衡：将请求分发到健康节点。
- 熔断机制：故障时快速拒绝请求，防止雪崩。

## 一致性（C）

在分布式系统中，**一致性**指所有节点在同一时刻看到的数据是相同的（强一致性）

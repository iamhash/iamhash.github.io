## 背景
Java在创建对象时，从把对象new出来到真正占用内存，其实是进行了一些分析与操作的，而不是直接分配在堆中。下面是详细说明：

<!-- more -->

## 分配流程

1.**逃逸分析**【决定是否放在堆中】 

- 逃逸分析：JVM通过分析对象的动态作用域，判断对象是否可能逃逸出当前方法或线程。（JVM的JIT（即时编译器）在优化时会做逃逸分析）：

  - 未逃逸：对象仅在方法内部使用，不会被外部方法或线程访问

    因此可以直接在栈上分配（栈帧中），方法执行完栈帧销毁，对象也随之销毁，不用 GC。

  - 方法逃逸：对象作为返回值或参数传递到其他方法。

    不能放栈里，必须放堆。

  - 线程逃逸：对象引用存入静态变量、成员变量，被其他线程访问；

    必须放堆，而且要考虑并发安全。

  这里需要注意：栈上分配并不是 Java 语言层面的保证，而是 JVM 优化行为，JDK 不同版本、不同 JIT 可能不一样。

2.**如果本线程的TLAB区域未满，则优先将对象分配到TLAB**

- JVM 的堆是多线程共享的，要避免并发分配锁竞争，于是给每个线程分配一小块私有区域 → TLAB（Thread Local Allocation Buffer）

- 当一个线程 new 对象时：会先看当前线程的 TLAB 是否还有空闲空间：

  有 → 直接把对象分配在 TLAB 中，几乎是无锁分配，非常快。

  没有 → 申请新的 TLAB，或者直接在堆上分配。

3.**对象分配在堆中**

- 如果无法栈上分配，也不能放进当前线程的 TLAB（比如 TLAB 太小装不下大对象），那就需要走堆分配流程：

- 新生代 Eden 区：绝大多数新对象分配在 Eden。

  大对象直接进老年代：如果对象太大，会绕过 Eden，直接放老年代（防止频繁复制）。

  Survivor 区复制晋升：对象经历 Minor GC 存活，会从 Eden → Survivor → 老年代晋升。

【堆分配是 GC 管理的主要区域，生命周期不确定，需要 GC 来判断是否可以回收。】

## 关于TLAB

### 什么是TLAB

TLAB 是 JVM 为了加速对象分配而引入的一种优化机制。本质是堆中的一小块内存，被独占地分配给某个线程。为了避免多线程分配对象时频繁加锁竞争，提高对象分配效率。

所在位置：仍然在堆上（属于新生代 Eden 区的一部分），只不过这块区域暂时只属于一个线程，别的线程不会碰。

### 为什么需要 TLAB

对象分配频率非常高，如果每次都去共享堆里申请，就要涉及**并发安全问题**，JVM 就得加锁或者用 CAS 等原子操作，非常影响性能。

大致思路为：先把堆中的一小块分给每个线程，线程内部自己用，不用竞争锁，快得多。

### 工作流程

1. 线程启动时：JVM 从 Eden 区划出一小块空间，作为这个线程的 TLAB。
2. 分配对象时：先检查当前线程的 TLAB 是否有足够的空闲空间：
   - 有 → 直接把对象放进去，无锁、快；
   - 没有 → 申请新的 TLAB 或直接在堆中分配。
3. TLAB 耗尽 / 线程结束时：剩余未用空间会被回收；TLAB 本身属于 Eden 区的一部分，最终由 GC 统一管理。

### TLAB 的特点与参数

TLAB 大小并不是固定的，可以通过 JVM 参数调节，比如：

```
-XX:+UseTLAB           # 启用 TLAB（默认一般是开启的）
-XX:TLABSize           # 设置每个 TLAB 的大小
-XX:+PrintTLAB         # 打印 TLAB 相关信息
```

大对象（例如数组）一般不会进入 TLAB，因为空间可能不足，会直接走堆分配。

TLAB 提升了分配效率，但也可能导致 Eden 区出现碎片。



特别注意：TLAB 不会被 GC 回收 是误区 —— 实际上它仍然属于堆的一部分，GC 照样回收，只是分配时不需要锁而已。
